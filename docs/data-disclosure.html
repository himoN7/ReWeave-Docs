Data disclosure

Last updated: 3 November 2026 Product: ReWeave (ReZephyr)

This page lists, in plain terms, what data ReWeave stores and what network requests it makes. It supplements the privacy policy.

No account required

ReWeave does not require you to sign in or create an account to use core features. There is no ReWeave-hosted user database.

Local storage (on your PC)

ReWeave stores app data locally under your Windows user profile, in %LocalAppData% (typically %LocalAppData%\ReZephyr\ReWeave or the package's per-app LocalState folder when installed from the Microsoft Store). This includes:

  • App settings and preferences (theme, layout, default densities, etc.)
  • Local pattern/palette libraries and simulation presets
  • Recent project history and autosave/crash-recovery snapshots

Project files you explicitly save (.reweave) are written wherever you choose — your Documents folder or any other location you pick in the Save / Save As dialog. ReWeave does not move or copy these files elsewhere on its own.

Uninstalling the app does not automatically delete files in %LocalAppData% or project files you saved outside the install folder. Delete them manually if you want a full cleanup.

Encrypted project files (.reweave)

.reweave files can be saved in an encrypted format (header WFSP1) so that project contents aren't readable as plain text if the file is opened outside ReWeave. Encryption is local only — it protects the file at rest on disk and is not a network or cloud feature.

Optional network activity

ReWeave's core simulation and design features work fully offline. The app makes network requests only when you explicitly trigger one of the following:

  • Local model. The current Store edition does not include Model Builder. If you point Weaver at a local server such as Ollama (http://127.0.0.1:11434) or LM Studio, the prompt goes to the address you typed. It leaves the PC only if that address is remote.
  • Weaver with a cloud AI provider: If you enable AI providers in Weaver settings and choose a cloud provider (Anthropic Claude, OpenAI, Google Gemini or an OpenAI-compatible endpoint), each Weaver turn sends your message, recent chat turns, and the draft details Weaver needs (weave structure, colours, yarn and sett settings, tool results) to that provider using the API key you entered. Your API key and workspace ID are stored on this PC encrypted with Windows DPAPI. With AI providers off, the Weaver works offline using ReWeave's built-in mill rules.
  • Update check / GitHub releases: ReWeave may check for newer versions using a DevWinUI update check control or by opening the project's GitHub Releases page in your browser when you click "Check for updates" or "Releases." This is a one-time, user-initiated request (or a lightweight version check) — ReWeave does not continuously upload your projects, simulation results, or usage data to any server.
  • Documentation and support links: Buttons such as "Email," "GitHub," "Portfolio," and "Privacy" open a link or your email client using the system browser/mail app. ReWeave does not track whether you click these.

Outside of the cases above, ReWeave does not phone home, does not run telemetry/analytics collection, and does not upload your weave designs, simulation data, or images to ReWeave-operated servers.

Local-only data

Everything Weaver writes stays in the local app-data folder above. Nothing in this list is sent anywhere by ReWeave.

  • Weaver chat history (WeaveAiChat\chat-history.json): your recent Weaver chats, including your messages, replies and the suggestion cards, so they appear under Recent chats. Clear and New chat in the pane manage it; deleting the file removes all history.
  • Saved prompts (WeaveAiChat): prompts you save from the prompt library.
  • Weaver memory (WeaveMemory\memory.json): design preferences Weaver keeps between turns of a project (for example the last structure and colourway), used to understand follow-up requests.
  • Usage statistics (Telemetry\copilot-turns-yyyyMM.jsonl): for each Weaver turn, its outcome, duration, mode, provider and model name, app version, and a random install ID. It never records your messages, replies, designs, file paths or keys. You can turn it off in Weaver settings → Privacy. Pilot sites can copy a report or the raw records from Settings → Weaver diagnostics and choose to share them.
  • Reliability record (reliability\app-sessions-yyyyMM.jsonl and reliability\app-faults-yyyyMM.jsonl): when the app started, how long it ran, and for anything that went wrong, the error's type name and the first few method names from its stack, with the app version and the same random install ID. It never records error messages, file paths, project names or designs — message text can contain the name of a file you opened, so it is left out on purpose. This is what tells us how often the app runs without a crash. It stays on your PC; ReWeave does not send it anywhere.
  • Crash log (logs\last-unhandled-exception.txt): the full text of the most recent unexpected error, kept so you can send it with a bug report if you choose. Unlike the reliability record, this one does include the error message and stack, which may name a file you had open. Nothing reads or sends it automatically; delete it at any time.
  • Earlier prompt samples (AiTrainingSamples\weave-ai-samples.jsonl): versions before 0.8.0 had a “Contribute to agent training” switch that, when turned on, saved prompts and the cards you applied to this file. It was never uploaded. The switch has been removed and ReWeave no longer writes the file; delete it if it exists.
  • Claude Desktop connector (MCP): If you install the ReWeave extension in Claude Desktop, Claude talks to the running app over a local named pipe on this PC. The pipe accepts connections only from programs running under your Windows account (for example Claude Desktop, VS Code or Cursor).

Third-party services

If you connect Weaver to a remote AI provider, that service handles the data under its own privacy policy. ReWeave does not control what the provider does with a turn you choose to send.
